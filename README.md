# vstore

文件版本内容存储库（Go），供上层版本库服务以库的方式调用，无接口层。
数据全部落在本地一个数据目录里，只用标准库，无外部依赖。

## 用法

```go
s, _ := vstore.Open("/path/to/data")
defer s.Close()

v1, _ := s.Commit("", content)        // 首个版本，父版本传空串
v2, _ := s.Commit(v1, content2)       // 之后每次提交指明父版本
v3, _ := s.Commit(v1, content3)       // 从任意旧版本继续提交 → 分支
v4, _ := s.Restore(v3, v1)            // 恢复：父版本 v3，内容等于 v1
data, _ := s.Read(v4)                 // 任意版本按标识读回，逐字节一致
```

## 设计

- **内容定义分块（CDC）**：gear 滚动哈希切分，最小 2 KiB / 平均 8 KiB / 最大 32 KiB。
  改一两行只影响附近的块，其余块边界不变。
- **内容寻址块存储**：每块按 SHA-256（前 16 字节）寻址，flate 压缩后落盘，
  相同内容的块全库只存一份（版本间、分支间天然去重），写入用临时文件 + rename 保证原子性。
- **版本清单**：每个版本一个紧凑二进制清单（父版本序号 + 有序块引用列表）。
  读取就是按清单取块、解压、拼接，O(文件大小)，没有 delta 链，历史再长读速也不衰减。
- 恢复（`Restore`）直接复用目标版本的块引用，不产生新块。

## 数据目录布局

```
data/
  chunks/xx/xxxx…    # 压缩后的内容块（按哈希前两位分目录）
  versions/v000000000001  # 每版本一个清单文件
```

## 测试

```sh
go test .          # 正确性 + 两个验收场景（长历史、分支与恢复）
go test -short .   # 只跑正确性测试
```

验收场景实测（Apple Silicon 本机）：1000 版长历史约 15.6 MiB、最慢单次读取约 11 ms；
双分支交替各 500 版约 20.2 MiB、最慢约 24 ms。均满足 ≤30 MiB、≤200 ms。
